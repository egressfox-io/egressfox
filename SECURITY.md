# Security

EgressFox is at repository-foundation stage. There are no supported runtime
releases, no production security guarantees, and no established response-time SLA.
The [threat model](docs/security/threat-model.md) records requirements and open risks.

## Reporting

Do not put subscription URLs, credentials, private keys, generated configurations,
or sensitive exploit details in public issues, discussions, or pull requests.

Check the repository's [Security page](https://github.com/egressfox-io/egressfox/security)
for a private vulnerability-reporting option. Its availability has not been
established by this bootstrap. If none is available, open only a minimal public
request for a confidential reporting channel, without vulnerability details or
sensitive data. Maintainers must establish and publish a private reporting process
before the first public runtime release; no private contact address is invented here.

For non-sensitive hardening proposals, a normal issue or design pull request is
appropriate. Reports should eventually include the affected version, sanitized
reproduction, impact, and suggested mitigation through the established channel.
